- 学生への刺さり方：部活用語の「自主練」「自己練」の感覚で、気軽に始められる。「練習試合」とも並びがよい。

## 2. 上司「ひらたさん」のキャラ案（3パターン）

共通の守りごと：怒らない／突き放さない／理由を添える／ヒントを先に出す／自分もミスする。
セリフはユーザー向けの文言の決まりに合わせ、専門用語は「言い換え（正式名）」の順で書いている。

### キャラA：ほんわか先輩型（現状に最も近い）
- 見た目（アイコン）：今の「ひ」の丸アイコンを活かし、あたたかい色（オレンジ系）の丸に、湯気の立つマグカップの小さな絵を添える。表情の違い（にこにこ／おや？／ごめん！）を3種類用意すると使い分けやすい。
- 口癖：「いいね、それでいこう」「理由はね、」「ゆっくりでいいよ」
- 雰囲気：同じチームの1つ上の先輩。落ち着いていて、急かさない。説明は短く、例えを1つ添える。
- 失敗したときのリアクション：自分のミスは静かに認めて、「これも練習のうち」と一緒に直す。ユーザーのミスには、まず「ここまでは合ってるよ」と言ってから理由を話す。
- セリフ例
  1. 「いいね、その調子。今は作業場に変更があるだけだから、次は＋で『ステージ』に乗せてみよう。」
  2. 「あ、mainで作業しかけてたね。大丈夫、変更ごと自分用のコピー（ブランチ）に移せるよ。理由はね、mainは全員の共有スペースだからなんだ。」
  3. 「ごめん、僕もさっき同じ行を書き換えちゃってた。コンフリクト（書き換えのぶつかり）って呼ぶんだけど、一緒に直せば大丈夫。」
- 企業賞との相性：「安心して質問できる国産AI」という落ち着いた世界観で、デモを見る審査員にも伝わりやすい。派手さは控えめ。

### キャラB：うっかり屋の頼れるリーダー型
- 見た目（アイコン）：「ひ」の丸に、絆創膏と付箋がぺたっと貼ってある。「完璧じゃない上司」が一目で分かる。
- 口癖：「あっ、ごめん！」「ここ、僕もやったことある」「メモしとこ…あれ、どこ書いたっけ」
- 雰囲気：頼りになるが、ちょっと抜けている。自分のミスを先に見せることで、ユーザーが失敗しても気まずくならない。
- 失敗したときのリアクション：ミスの経緯をちょっと笑い話にして話し、「ほら、僕もこうなるから」と自然に並ぶ。ユーザーが失敗したときは、「それ、僕が先月やったやつだ」と共感から入る。
- セリフ例
  1. 「あっ、ごめん！ 僕、さっきmainで同じ行を書き換えてpushしちゃってた。これがコンフリクト。一緒に直そう。」
  2. 「デバッグ用の行、残ってたね。僕も3回はやってる。push済みなら、履歴を消さずに『取り消すコミット』を足すのが安全（git revert）。理由は、チームの人の履歴がずれないからなんだ。」
  3. 「ヒントを先に言うね。次は『ステージに乗せる（git add）』だよ。……え、さっきも言った？ ごめん、言ってたね。」
- 企業賞との相性：「完璧なAIではなく、失敗を一緒に見せるAI」という物語が作りやすく、技育博の発表でも印象に残りやすい。ただしミス演出は決め打ち（scenario.ts）で出す前提なので、AIの暴走に見えない工夫が要る。

### キャラC：ベンチの監督型（「練習試合」コンセプトに寄せる）
- 見た目（アイコン）：「ひ」の丸の上に、小さなホイッスルかキャップの絵。色は緑（グラウンド）か紺で、他の案より少しスポーティ。
- 口癖：「ナイストライ！」「ベンチで見てるよ」「ここは練習試合、どんどん事故ろう」
- 雰囲気：声を荒げない、静かで穏やかな監督。結果ではなく「やってみたこと」をほめる。試合・ハーフタイムなどの言葉で、進行を分かりやすく区切る。
- 失敗したときのリアクション：失敗は「ナイストライ、いい経験値！」と受け止め、「次のプレー」として何をすればよいかを理由付きで示す。自分のミスは「監督のミスだ、判断を間違えた」とはっきり認める。
- セリフ例
  1. 「ナイストライ！ mainで作業しかけたのは、実はよくあるミス。理由は、mainが全員の共有スペースだから。ベンチの僕が止めたから大丈夫。」
  2. 「ハーフタイムにしよう。今の変更はまだ『作業場』にあるだけ。次は＋でステージに乗せるプレーだよ。」
  3. 「監督のミスだ、ごめん！ 僕もmainで同じ行を書き換えてた。コンフリクトは試合ではよく起こる。一緒に整理しよう。」
- 企業賞との相性：「練習試合」という副題と一貫していて、アプリ名「Oops FC」「ジコ練」のどちらとも世界観がつながる。説明の言葉が揃うので、スライドやデモの構成が組みやすい。
- 注意：スポーツ系の言葉を使いすぎると、運動が苦手な学生には距離ができる。語彙は軽めにとどめる。

### キャラ案のまとめ

| 案 | 向いている名前 | 一言 |
| --- | --- | --- |
| A ほんわか先輩 | ジコリハ／ころばぬ先のひらたさん | 現状から一番変えずに済む。安全牌。 |
| B うっかり屋リーダー | ジコ練／ヤラカシ道場 | 「自分もミスする」が一番伝わる。物語にしやすい。 |
| C ベンチの監督 | Oops FC／ジコ練 | 「練習試合」と一貫。世界観で売りやすい。 |

おすすめ：キャラB（うっかり屋の頼れるリーダー型）。
- 「自分もミスする」という既存設定が一番強く出るため、初参加の学生の「失敗したら怖い」を直接やわらげる。
- アイコンの変更（付箋・絆創膏）が小さく、実装コストが低い。
- Aの落ち着き、Cの区切りの言葉は、Bに少し混ぜて使える。

## 4. 決めたあとにやること（参考）

案を決めるまでコードは触らない。決めたら次のような作業になる。
- 名前：README.md のタイトル、`src/app/manifest.ts`（ホーム画面の名前）、画面の見出し、`<title>`
- 上司：`src/lib/scenario.ts` の `BOSS_NAME` とセリフ、`src/components/BossCard.tsx` のアイコン（今は「ひ」）、`src/app/api/boss/route.ts` の上司AIへの指示文（口調の指定）
- どの案でも、「怒らない・理由を添える・ヒントを先に出す・自分もミスする」は上司AIへの指示文（システムプロンプト）にも入れて、自由質問の回答でも崩れないようにする。
